Where a token sits

Attention can tell you which tokens relate — but on its own, it can't tell you their order. Position has to be added. The elegant way bakes it into the math itself.

problem Attention is blind to order

The Query·Key·Value math treats the context as a bag of tokens. Shuffle them and attention computes the same relationships, just rearranged — it's permutation-invariant. Permute the input, you simply permute the output:

permutation invariance
Attn(πX) = π · Attn(X)
ordering A
thedogbittheman
ordering B
themanbitthedog
Same tokens, opposite meaning. Without position, the model can't tell these apart.
v1 · 2017 Absolute — stamp each slot with a wave fingerprint

The original fix: before layer 1, add a position-dependent vector to each token. Each dimension is a sine or cosine at a different frequency, so every position gets a unique "barcode" the model learns to read.

sinusoidal positional encoding
PE(pos,2i)=sin(pos / 10000^(2i/d)), PE(pos,2i+1)=cos(pos / 10000^(2i/d))
−1+1rows = position · columns = dimension

Read a single row and you get that position's fingerprint. It works — but it's absolute: it labels slot 5 and slot 105, when what attention usually wants is the distance between two tokens. The model has to work that out, and it generalizes poorly past lengths it trained on.

v2 · RoPE Rotary — encode position as rotation

The modern trick doesn't add anything. It rotates each Query and Key by an angle proportional to its position. Treat dimensions in pairs as points on a circle, and spin each pair by position × frequency:

rotate the query at m, the key at n
q̃ₘ = R(mθ)·q, k̃ₙ = R(nθ)·k, R(θ)=[[cosθ,−sinθ],[sinθ,cosθ]]

Now the payoff. Take the dot product of a rotated query at position m with a rotated key at position n. The two rotations combine — and the absolute positions cancel, leaving only their difference:

★ the whole point
⟨R(mθ)q, R(nθ)k⟩ = qᵀ R((n−m)θ) k

The attention score depends only on (n − m) — the gap between the tokens, never where they sit absolutely. Relative position falls out for free, at every layer, with zero added parameters.

try it Only the gap turns the dial

Two tokens, a query and a key. Drag the slider to change the distance between them. The query arrow stays put; the key arrow rotates by gap × θ. The relevance score tracks the angle between them — and nothing else.

gap angle 0°  =  (n−m) × θ
relevance ∝ cos(gap) = 1.00
Watch: the absolute positions of the two tokens never appear. Slide to any distance — only the difference sets the angle, and the angle sets the score. That's relative position, built straight into the geometry.

Low dimensions — fast spin

Rotate quickly per step, so they resolve fine, local distance — neighbors and short phrases.

High dimensions — slow spin

Rotate slowly, so they stay distinct over long ranges — relationships thousands of tokens apart.

Why it matters downstream

Because RoPE only cares about relative distance and uses a spread of frequencies, you can stretch the context window after training by slowing the rotations (the idea behind NTK / YaRN scaling). That's a big part of how models grew from a few thousand tokens to hundreds of thousands.

It also closes the loop on the last diagram: attention finds which tokens matter; position tells it where they are relative to each other. Together they're why "the dog bit the man" and "the man bit the dog" finally read differently.
